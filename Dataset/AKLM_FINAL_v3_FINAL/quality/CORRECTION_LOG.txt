4. STALE-CASE COVERAGE GAPS (v3.1 derived-label extension)
Finding: stale_cases.csv contained 1,200 rows covering only 6 of the 10 website x version-pair combos per

521 questions referenced 520 stale scenarios; 460 referenced a (stale, required) tuple with stale < required

Action: extended stale_cases.csv to the full cross-product (200 websites x 10 pairs = 2,000 rows).
Every original row was preserved untouched; new rows are flagged added_cover_gap=yes.
Result: 100% of stale questions with stale < required now link 1:1 to a stale_case row; fresh-index
questions (V01->V01) intentionally have no case and resolve to a "safe, no refresh needed" gold.
This includes the previously missing V08->V10 and V09->V10 pairs.

5. CONFLICT-CASE COVERAGE (v3.1 derived-label extension)
Finding: conflict_cases.csv had a row for only 150 of 200 websites.
Action: added one deterministic record for each of the 50 missing websites (flagged added_cover_gap=yes),
and added resolution metadata to all rows: resolved_version = max(version_a, version_b),
snapshot_is_newer, resolution_rule = prefer_authoritative_newer_of_pair.
Result: 200/200 websites covered; 100% of conflict questions link to their website's conflict record.

6. GOLD ANSWERS (v3.1 derived-label extension)
Finding: questions.csv carried only coarse expected_behavior strings ("Retrieve the version pair and
classify the change") with no resolved answers, supporting chunks, or citations.
Action: added derivation columns that are deterministic functions of the canonical corpus and
lifecycle/changes.csv: gold_answer, supporting_chunk_ids, citation_required_document_ids,
gold_available, gold_derivation, version_a/version_b, snapshot_version, stale_case_id, conflict_id.
Result: 5,200/5,200 rows gold_available=yes with non-empty gold dropped from corpus entities;
4680 questions carry supporting chunk ids; retrieval_control carries none by design.
Semantics:
- comparison: policy page entity diff (identical version pair -> "No change").
- change_detection: change_type lookup from changes.csv; V01 = initial release (no predecessor).
- stale: refresh decision + chunk ids to swap.
- historical: pricing page at requested version + diff vs V10.
- conflict: current authoritative release governs; older snapshot superseded.
- policy/freshness/requirement: deterministic render of target page entities.
- multi_document: combined services (P09) + support (P04) render.
- retrieval_control: arithmetic answer, no retrieval.

7. CHUNK-LEVEL DIFFS (v3.1 derived-label extension)

consecutive-version content change rate. embedding_affected is assigned deterministically from text
equality (documented decision; requires_reembedding='conditional' for reordering is retained as the
original signal without an embedding-model dependency).
